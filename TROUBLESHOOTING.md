# Устранение неполадок - Inline Редактор

## Ошибка 404 при сохранении

### Симптомы:
- В консоли браузера появляется ошибка: `Failed to fetch` или `404 (Not Found)`
- При редактировании контента изменения не сохраняются в базу данных
- Появляются синие индикаторы 💾 вместо зеленых ✅

### Причина:
API сервер не запущен или недоступен по адресу `http://localhost:3001`

### Решение:

#### 1. Запуск API сервера

**Автоматический способ (рекомендуется):**
1. Запустите файл `start-server.bat` в корневой папке проекта
2. Дождитесь сообщения "API сервер запущен на порту 3001"

**Ручной способ:**
1. Откройте командную строку (cmd)
2. Перейдите в папку проекта:
   ```cmd
   cd путь\к\проекту\server
   ```
3. Установите зависимости (если еще не установлены):
   ```cmd
   npm install
   ```
4. Запустите сервер:
   ```cmd
   npm start
   ```

#### 2. Проверка статуса

1. Откройте браузер и перейдите на: http://localhost:3001/api/health
2. Если сервер работает, вы увидите JSON ответ:
   ```json
   {
     "status": "ok",
     "timestamp": "2025-01-08T22:30:00Z",
     "version": "1.0.0"
   }
   ```

3. Или используйте встроенную страницу статуса: [api-status.html](api-status.html)

#### 3. Проверка в редакторе

1. Откройте любую страницу сайта
2. Войдите как администратор
3. Активируйте режим редактирования
4. Должно появиться сообщение: "✅ Подключение к базе данных установлено"

### Fallback режим

Если API сервер недоступен, редактор автоматически переключается в fallback режим:

- **Индикатор:** Синий значок 💾 с анимацией
- **Сообщение:** "Сохранено локально (API сервер недоступен)"
- **Хранение:** Изменения сохраняются в localStorage браузера
- **Ограничения:** Данные доступны только в текущем браузере

## Другие возможные проблемы

### Порт 3001 занят

**Симптомы:**
- Ошибка при запуске: "Port 3001 is already in use"

**Решение:**
1. Найдите процесс, использующий порт:
   ```cmd
   netstat -ano | findstr :3001
   ```
2. Завершите процесс или перезагрузите компьютер

### Node.js не установлен

**Симптомы:**
- Ошибка: "node is not recognized as an internal or external command"

**Решение:**
1. Скачайте и установите Node.js с https://nodejs.org/
2. Выберите LTS версию
3. Перезапустите командную строку

### Проблемы с зависимостями

**Симптомы:**
- Ошибки при выполнении `npm install`

**Решение:**
1. Удалите папку `node_modules`:
   ```cmd
   rmdir /s node_modules
   ```
2. Удалите файл `package-lock.json`
3. Переустановите зависимости:
   ```cmd
   npm install
   ```

### База данных не создается

**Симптомы:**
- Ошибки при сохранении в API
- Отсутствует файл `server/content.db`

**Решение:**
1. Убедитесь, что у пользователя есть права на запись в папку `server`
2. Перезапустите API сервер
3. База данных создается автоматически при первом запуске

## Диагностика

### Проверка логов сервера

При запуске сервера в консоли должны появиться сообщения:
```
Подключение к SQLite базе данных установлено
API сервер запущен на порту 3001
Доступен по адресу: http://localhost:3001
```

### Проверка логов браузера

Откройте Developer Tools (F12) и проверьте вкладку Console:
- **Успешное сохранение:** "Изменение сохранено в БД"
- **Fallback режим:** "API сервер недоступен, сохраняем в localStorage"
- **Ошибки:** Красные сообщения об ошибках

### Тестирование API

Используйте curl или Postman для тестирования API:

```bash
# Проверка здоровья
curl http://localhost:3001/api/health

# Получение контента страницы
curl http://localhost:3001/api/content/pyramid
```

## Контакты для поддержки

Если проблема не решается:
1. Проверьте все пункты выше
2. Сохраните логи ошибок из консоли браузера и сервера
3. Опишите шаги, которые привели к проблеме
